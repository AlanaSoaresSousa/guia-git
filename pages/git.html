GIT / CONTROLE DE VERSÃO

Entenda o Git.

Git é um sistema de controle de versão utilizado para acompanhar e gerenciar as alterações feitas em arquivos de um projeto, principalmente em projetos de programação.


Ele permite registrar diferentes versões do código, recuperar alterações anteriores, criar ramificações (branches) para trabalhar em funcionalidades separadas e juntar essas alterações posteriormente.


Dessa forma, o Git facilita a organização do desenvolvimento, evita a perda de informações e permite que várias pessoas trabalhem no mesmo projeto de maneira mais segura e organizada.

02 / HISTÓRIA

História e origem do Git

O Git foi criado em 2005 por Linus Torvalds, o principal desenvolvedor do sistema operacional Linux. A criação do Git aconteceu porque a equipe responsável pelo desenvolvimento do Linux precisava de uma nova ferramenta para controlar as diversas alterações realizadas no código-fonte do projeto.

A ferramenta de controle de versão utilizada anteriormente deixou de ser uma opção adequada, criando a necessidade de desenvolver uma alternativa que fosse rápida, segura, eficiente e distribuída. Linus Torvalds desenvolveu então o Git com o objetivo de facilitar o trabalho de vários programadores ao mesmo tempo, permitindo que cada desenvolvedor tivesse uma cópia completa do projeto e pudesse registrar suas alterações localmente.

Com o passar dos anos, o Git foi aprimorado e passou a ser utilizado em diversos tipos de projetos de software, tornando-se uma das ferramentas de controle de versão mais populares do mundo. Sua evolução também contribuiu para o crescimento de plataformas como o GitHub, que utiliza o Git para facilitar o armazenamento, compartilhamento e colaboração em projetos de programação.

Por que ele foi criado?

O objetivo era ter uma ferramenta distribuída, rápida, confiável e capaz de lidar com projetos muito grandes e com milhares de alterações realizadas por diferentes desenvolvedores.

03 / BENEFÍCIOS

Por que usar Git?

O Git facilita a organização do desenvolvimento e oferece segurança para experimentar novas ideias sem comprometer o código principal.

Motivo_01

Histórico

O Git registra as alterações feitas no projeto por meio dos commits. Isso permite acompanhar a evolução do código, saber o que foi alterado e recuperar versões anteriores quando necessário.

motivo_02

Segurança

O Git ajuda a proteger o projeto contra a perda de informações, pois mantém diferentes versões dos arquivos. Caso uma alteração cause algum problema, é possível consultar ou restaurar uma versão anterior.

motivo_03

Organização

O Git facilita a organização do desenvolvimento, permitindo separar diferentes funcionalidades por meio de branches e registrar cada etapa do projeto de forma estruturada. Isso evita que todas as alterações sejam feitas diretamente na versão principal.

motivo_04

Colaboração

O Git permite que várias pessoas trabalhem no mesmo projeto, cada uma podendo desenvolver diferentes partes e depois integrar suas alterações. Dessa forma, facilita o trabalho em equipe e ajuda a controlar as modificações feitas por cada integrante.

04 / FUNCIONAMENTO

Como o Git funciona?

O Git funciona como um sistema que acompanha e registra as alterações realizadas nos arquivos de um projeto. O desenvolvedor modifica os arquivos em seu diretório de trabalho (Working Directory), seleciona as alterações que deseja registrar na Staging Area e, em seguida, cria um commit, que salva aquele conjunto de modificações no histórico do projeto.

O Git permite criar branches para desenvolver funcionalidades separadamente e depois unir as alterações por meio de um merge. Além disso, o projeto pode ser enviado para um repositório remoto, como o GitHub, permitindo armazenar o código e compartilhá-lo com outras pessoas.

01

Working Directory

É a pasta onde você trabalha e modifica os arquivos do seu projeto.

02

Staging Area

Área onde você seleciona as alterações que deseja incluir no próximo commit.

03

Repositório local

Local onde o Git armazena os commits e o histórico completo do projeto.

Fluxo das alterações

Working Directory → Staging Area → Repositório Local

05 / VERSIONAMENTO

Controle de versão

O controle de versão do Git é o sistema responsável por registrar, organizar e acompanhar as alterações feitas em um projeto ao longo do tempo.


Ele permite que o desenvolvedor saiba o que foi modificado, quando a alteração aconteceu e possa consultar ou recuperar versões anteriores dos arquivos. Dessa forma, o Git ajuda a evitar a perda de código, facilita a correção de erros e permite que diferentes versões de um projeto sejam gerenciadas de maneira organizada.

O que isso permite?

É possível saber o que foi alterado, quando a alteração aconteceu, quem realizou a mudança e recuperar versões anteriores do projeto.

06 / REPOSITÓRIO

Repositório local

Um repositório local é a cópia de um projeto do Git que fica armazenada no próprio computador do desenvolvedor. Ele contém os arquivos do projeto e também o histórico das alterações registradas por meio dos commits.


No repositório local, é possível modificar arquivos, criar branches, fazer commits e consultar versões anteriores sem precisar estar conectado à internet. Posteriormente, as alterações podem ser enviadas para um repositório remoto, como o GitHub, para serem compartilhadas com outras pessoas.

CRIAR REPOSITÓRIO

LOCAL

$ git init

Initialized empty Git repository

O comando git init transforma a pasta atual em um repositório Git.

07 / WORKING DIRECTORY

Working Directory

O Working Directory (diretório de trabalho) é a pasta do projeto onde o desenvolvedor trabalha diretamente nos arquivos. É nesse local que você cria, edita, exclui ou modifica arquivos antes de registrar essas alterações no Git.


As mudanças feitas no Working Directory ainda não fazem parte de um commit; primeiro, elas podem ser enviadas para a Staging Area usando git add e, depois, registradas no histórico com git commit. Em resumo, é o espaço onde as alterações do projeto acontecem.

Exemplo

Ao criar, editar ou excluir um arquivo dentro da pasta do projeto, você está realizando alterações no Working Directory.

08 / STAGING AREA

Staging Area

A Staging Area é uma área intermediária do Git onde você seleciona e prepara as alterações que deseja incluir no próximo commit. Depois de modificar arquivos no Working Directory, você utiliza o comando git add para colocar essas alterações na Staging Area.


Isso permite escolher exatamente quais mudanças serão registradas, antes de salvá-las definitivamente no histórico com o comando git commit. Em resumo, a Staging Area funciona como uma etapa de preparação entre a edição dos arquivos e o registro das alterações.

ADICIONAR ALTERAÇÃO

$ git add arquivo.html

Para adicionar todos os arquivos modificados, também é possível utilizar: 

$ git add .

09 / COMMITS

Commits

Um commit é um registro das alterações feitas em um projeto no Git. Ele funciona como um ponto de salvamento, armazenando as mudanças que foram selecionadas na Staging Area e adicionando-as ao histórico do projeto.


Cada commit pode receber uma mensagem que explica o que foi alterado, facilitando a identificação e o acompanhamento das diferentes etapas do desenvolvimento. O comando utilizado para criar um commit é git commit -m "mensagem".

CRIAR COMMIT

$ git commit -m "Adiciona página inicial"

A mensagem do commit deve explicar de forma clara o que foi alterado.

10 / HISTÓRICO

Histórico de alterações

O histórico de alterações do Git é o registro de todas as modificações que foram salvas no projeto por meio dos commits. Ele permite acompanhar a evolução do projeto ao longo do tempo, identificando quais alterações foram feitas e em que momento.


Esse histórico também possibilita consultar versões anteriores dos arquivos e entender como o código chegou ao estado atual. Dessa forma, o histórico de alterações ajuda no controle, organização e recuperação do projeto quando necessário.

CONSULTAR HISTÓRICO

$ git log

O comando mostra informações como os commits, autores, datas e mensagens registradas.

11 / BRANCHES

Branches

As branches (ramificações) são versões independentes de um projeto dentro do Git, usadas para desenvolver funcionalidades, fazer correções ou testar mudanças sem alterar diretamente a versão principal. Cada branch possui seu próprio histórico de commits, permitindo que diferentes partes do projeto sejam desenvolvidas separadamente.


Depois que uma alteração é concluída e testada, ela pode ser integrada à branch principal por meio de um merge. Dessa forma, as branches ajudam a manter o projeto mais organizado, seguro e adequado para o trabalho em equipe.

CRIAR BRANCH

$ git checkout -b "sua branch"
  $ git switch "sua branch"

13 / CONFLITOS

Conflitos

Os conflitos no Git acontecem quando duas alterações diferentes são feitas na mesma parte de um arquivo e o Git não consegue decidir automaticamente qual delas deve ser mantida. Isso é comum quando duas pessoas trabalham em branches diferentes e depois tentam unir seus códigos usando um merge.


Quando ocorre um conflito, o Git marca a parte do arquivo que precisa ser analisada, e o desenvolvedor deve escolher se vai manter uma alteração, a outra ou combinar as duas. Depois de resolver o conflito, é necessário salvar o arquivo e realizar um novo commit para registrar a solução. Assim, os conflitos fazem parte do trabalho colaborativo e exigem que os desenvolvedores revisem as alterações antes de integrá-las.

Como resolver?

Para resolver um conflito no Git, primeiro você precisa identificar quais partes do arquivo foram alteradas de maneiras diferentes. O Git marca essas partes com símbolos como <<<<<<<<, ======= e >>>>>>>. Você deve abrir o arquivo, analisar as duas versões e escolher qual alteração manter ou combinar as duas, removendo esses marcadores. Depois, salve o arquivo e informe ao Git que o conflito foi resolvido. Por fim, finalize a resolução criando um commit com git commit -m "Resolve conflito". Em resumo: identificar o conflito → escolher/combinar as alterações → remover os marcadores → git add → git commit.

14 / REMOTO

Repositório remoto

Um repositório remoto é uma versão do projeto armazenada em um servidor ou serviço online, permitindo que o código e o histórico do Git sejam acessados e compartilhados por diferentes pessoas.


Ele é utilizado para enviar as alterações feitas no repositório local, usando comandos como git push, e também para baixar alterações feitas por outros desenvolvedores, usando git pull ou git fetch. Um exemplo de serviço que hospeda repositórios remotos é o GitHub. Dessa forma, o repositório remoto facilita o backup, compartilhamento e trabalho colaborativo em projetos.

GitHub e outros serviços

Plataformas como o GitHub podem hospedar repositórios Git remotos. O Git, por sua vez, continua sendo a ferramenta responsável pelo controle de versão.

15 / ORGANIZAÇÃO

.gitignore

O .gitignore é um arquivo utilizado pelo Git para indicar quais arquivos e pastas devem ser ignorados e não devem ser enviados para o repositório. Ele é útil para evitar que arquivos desnecessários ou que não precisam fazer parte do projeto sejam adicionados aos commits, como arquivos temporários, configurações pessoais, pastas de dependências e arquivos gerados automaticamente.


Por exemplo, ao colocar *.log no .gitignore, os arquivos com extensão .log serão ignorados pelo Git. Dessa forma, o .gitignore ajuda a manter o repositório mais organizado e limpo, contendo apenas os arquivos realmente importantes para o projeto.

EXEMPLO DE .GITIGNORE

node_modules/
  .env
  *.log
  .DS_Store

Ele é útil para evitar o versionamento de arquivos temporários, informações sensíveis e arquivos gerados automaticamente.

16 / COMPARAÇÃO

Git × GitHub

Apesar de trabalharem juntos, Git e GitHub são coisas diferentes.

GIT

Controle de versão

O Git é um sistema de controle de versão utilizado para acompanhar e registrar as alterações feitas em um projeto. Ele funciona principalmente no computador do desenvolvedor e permite criar commits, branches, realizar merge, consultar o histórico de alterações e recuperar versões anteriores do projeto. O Git pode ser utilizado mesmo sem internet, já que grande parte de suas funções acontece no repositório local.

GITHUB

Plataforma de colaboração

O GitHub é uma plataforma online que permite armazenar repositórios Git em servidores remotos e facilitar o compartilhamento e a colaboração entre desenvolvedores. Ele oferece recursos como pull requests, issues, revisão de código e gerenciamento de projetos. Diferentemente do Git, o GitHub depende de uma plataforma online para hospedar os projetos e permitir que outras pessoas tenham acesso a eles.

17 / FLUXO

Fluxo básico de trabalho com Git

Um fluxo básico consiste em modificar os arquivos, selecionar as alterações, criar um commit e, quando necessário, enviar as alterações para um repositório remoto.

Editar → git add → git commit → git push 

$ git status
  $ git add .
  $ git commit -m "Atualiza projeto"
  $ git push

18 / BOAS PRÁTICAS

Boas práticas de commits

Bons commits tornam o histórico mais organizado e facilitam a compreensão das alterações realizadas no projeto.

01

Seja claro

Escreva mensagens que expliquem objetivamente a alteração.

02

Commits pequenos

Evite colocar muitas alterações diferentes em um único commit.

03

Use verbos

Prefira mensagens como "Adiciona", "Corrige" e "Atualiza".

04

Organize o histórico

Faça commits relacionados a uma tarefa ou mudança específica.

Terminal

$ git commit -m "correção na main"

19 / CONFIGURAÇÃO

Configuração inicial do Git

Antes de começar a criar commits, é recomendado configurar o nome e o e-mail que serão associados às suas alterações.

GIT CONFIG

USER INFORMATION

$ git config --global user.name "Seu Nome"

  $ git config --global user.email "seu@email.com"

VERIFICAR CONFIGURAÇÕES

$ git config --list

Esse comando permite visualizar as configurações atualmente definidas no Git.
