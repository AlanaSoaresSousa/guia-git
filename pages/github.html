DESENVOLVIMENTO COLABORATIVO

GitHub

O GitHub é uma plataforma de desenvolvimento colaborativo que reúne código, projetos e pessoas. Com ele, você pode compartilhar seus projetos, colaborar com outros desenvolvedores, revisar código, organizar tarefas e automatizar processos.

O Git é o sistema de controle de versões que registra a história do código. O GitHub é a plataforma online construída ao redor dele, oferecendo um espaço para armazenar projetos, discutir mudanças e trabalhar em equipe

03 / REPOSITÓRIOS

Seu projeto, em um lugar compartilhável.

Um repositório reúne código, documentação, histórico, branches, Issues, Pull Requests e configurações de um projeto.

01

Como criar um repositório?

Para criar um repositório, acesse o GitHub, clique em New repository e informe o nome do projeto. Depois, escolha se ele será público ou privado. Também é possível adicionar um README, um arquivo .gitignore e escolher uma licença durante a criação.

Depois de criado, o GitHub apresenta as opções para começar o projeto diretamente pela plataforma ou conectar um projeto que já existe no seu computador utilizando o Git.

02

Público ou privado?

Ao criar um repositório, você pode escolher entre torná-lo público, permitindo que outras pessoas visualizem o projeto, ou privado, restringindo o acesso às pessoas autorizadas.

03

O que ele pode conter?

Além dos arquivos do projeto, um repositório pode conter README, branches, Issues, Pull Requests, releases e workflows de automação.

04 / PERFIL

Seu GitHub também conta sua história.

Um perfil pode apresentar sua biografia, tecnologias, contribuições, repositórios fixados e projetos relevantes. O Profile README permite colocar uma apresentação no topo do perfil por meio de um repositório público com o mesmo nome de usuário.

Para criar o seu, basta criar um novo repositório público com exatamente o mesmo nome do seu usuário do GitHub. Depois, adicione um arquivo README.md na raiz desse repositório e escreva nele a apresentação que deseja exibir no seu perfil. Quando o repositório estiver configurado corretamente, o conteúdo do README aparecerá automaticamente na página do seu perfil.

Exemplo: se seu usuário for joao123, o repositório deverá se chamar joao123.

06 / PULL REQUESTS

Proponha, revise e integre.

Um Pull Request propõe integrar uma branch em outra. Ele cria um espaço para comparar arquivos, comentar trechos, solicitar ajustes, aprovar e realizar o merge.

Um Pull Request pode ser criado por meio de comandos do Git, utilizando o terminal, ou diretamente pela interface do GitHub.

Pela interface, é possível visualizar os arquivos modificados, comparar as alterações linha por linha, acompanhar comentários e revisões, verificar os testes automáticos e realizar a aprovação ou o merge da alteração.

07 / ISSUES

Transforme problemas em tarefas.

Issues são utilizadas para registrar e acompanhar assuntos relacionados a um projeto, como bugs, tarefas, sugestões, dúvidas e ideias. Cada Issue possui um título e uma descrição, permitindo explicar o que precisa ser resolvido ou discutido.

Depois de criada, a Issue pode receber comentários, etiquetas, responsáveis e outros recursos para organizar o trabalho. Conforme o problema ou tarefa avança, a equipe pode acompanhar sua situação até que ela seja concluída e encerrada.

08 / PROJECTS

Organize o trabalho e acompanhe o progresso.

O GitHub Projects permite organizar e acompanhar o trabalho de um projeto utilizando diferentes tipos de visualização, como quadros e listas. Ele pode ser utilizado para acompanhar Issues, Pull Requests e outras tarefas ao longo do desenvolvimento.

Uma equipe pode organizar as tarefas de acordo com seu estado, no estilo Kanban, definindo etapas como "A fazer", "Em andamento", "Em revisão" e "Concluído". Assim, fica mais fácil visualizar o que precisa ser feito, o que está sendo desenvolvido e o que já foi finalizado.

09 / AUTOMAÇÃO

Actions coloca o projeto em movimento.

O GitHub Actions permite automatizar tarefas por meio de workflows que podem ser executados quando eventos, como um push ou Pull Request, acontecem. Ele também pode ser utilizado em práticas de CI/CD, automatizando testes, builds e publicação de aplicações.

CI/CD

CI (Continuous Integration) é a prática de integrar alterações ao projeto continuamente, realizando verificações e testes automatizados para identificar problemas.

CD (Continuous Delivery/Deployment) automatiza etapas de entrega ou publicação da aplicação após as alterações serem verificadas.

Para praticar e enteder melhor, consulte os guias do GitBase ou procure tutoriais práticos sobre GitHub Actions.

11 / COMUNIDADE

Comece com uma cópia

DISCUSSIONS

Converse sobre ideias

Use discussões para perguntas, anúncios, ideias e trocas mais abertas com a comunidade.

CONTRIBUA

Corrija bugs, melhore a documentação ou crie funcionalidades e envie um Pull Request.

12 / IA E AGENTS

Do problema à implementação.

O GitHub oferece recursos de inteligência artificial que podem auxiliar no desenvolvimento de software. Além de sugerir e gerar código, agentes podem trabalhar com o contexto de uma tarefa, analisar o projeto, propor alterações e realizar etapas do desenvolvimento.

Agentes de desenvolvimento

Um agente pode receber uma tarefa e trabalhar em diferentes etapas, como analisar o código, implementar uma solução e verificar as alterações realizadas.
