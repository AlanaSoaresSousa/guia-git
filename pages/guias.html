Objetivo Começar um projeto no computador utilizando Git e conectá-lo a um repositório no GitHub.

01. Criando a pasta do projeto

Primeiro, tenha uma pasta onde ficarão os arquivos do projeto. Abra o terminal dentro dela para que os próximos comandos atuem no lugar certo.

02. Inicializando o Git

O comando abaixo transforma a pasta em um repositório Git local, criando a estrutura que guarda o histórico. 

git init

03. Verificando o repositório

Use git status para conferir o estado atual dos arquivos e saber o que o Git está acompanhando. 

git status

04. Criando o repositório no GitHub

Agora crie um repositório remoto no GitHub. Ele ficará hospedado na plataforma e poderá receber o histórico do seu computador. acesse a seção github para aprender a criar um repositório remoto. 

Computador
└── Repositório local

        ↕ conexão

GitHub
└── Repositório remoto

05. Conectando os dois

origin é o nome normalmente usado para identificar o remoto principal. Este comando registra a URL do GitHub no projeto local. 

git remote add origin URL_DO_REPOSITORIO

06. Verificando a conexão

Confira os endereços configurados e se eles serão usados para leitura e envio. 

git remote -v
Conceito importanteRepositório local fica no computador.Repositório remoto fica no GitHub.git remote add origin estabelece a referência entre os dois. 
                  Criar projeto  →  git init  →  Criar no GitHub  →  git remote add origin  →  Local conectado ao remoto

Objetivo Registrar alterações no histórico local e enviá-las para o GitHub com segurança.

01. Verificando alterações

Antes de preparar qualquer coisa, veja quais arquivos foram modificados, adicionados ou ainda não são rastreados. 

git status

02. Adicionando arquivos

git add . coloca as alterações na staging area, a área de preparação do próximo commit. 

git add .

03. Criando um commit

O commit registra uma versão das alterações no histórico local. A mensagem deve explicar o que mudou. 

git commit -m "Minha primeira alteração"
Importante Commit não envia o projeto para o GitHub. Ele só registra a versão localmente.

04. Enviando para o GitHub

push envia os commits locais para o repositório remoto. 

git push origin main
Arquivos modificados → git add → Staging Area → git commit → Histórico local → git push → GitHub
Vocabulário do fluxoWorking directory é onde você edita os arquivos.Staging area reúne o que entrará no próximo commit.Commit cria um ponto no histórico; push o envia ao remoto.

Objetivo Entender a diferença entre obter um projeto pela primeira vez e atualizar um projeto que já está no computador.

01. Clonando pela primeira vez

git clone copia o repositório remoto para o computador e já configura sua conexão com o GitHub. 

git clone URL_DO_REPOSITORIO
cd nome-do-projeto
GitHub
   ↓
git clone
   ↓
Computador

02. Atualizando o projeto

Quando o projeto já foi clonado, use git pull para buscar alterações novas e integrar as mudanças ao repositório local. 

git pull
GitHub
   ↓
git pull
   ↓
Projeto local atualizado
Conceito importantegit clone é usado normalmente para obter um projeto pela primeira vez.git pull atualiza um projeto que já foi clonado.

Objetivo Desenvolver em uma linha separada, integrar o trabalho na main e entender o que fazer quando alterações entram em conflito.

01. Criando e trocando de branch

Uma branch cria uma linha separada de desenvolvimento. Assim, você experimenta sem alterar diretamente a versão principal. 

git branch nova-feature
git switch -c nova-feature
git switch nova-feature

02. Trabalhando na branch

Faça as alterações normalmente e registre o resultado na branch da funcionalidade. 

git add .
git commit -m "Adiciona nova funcionalidade"

03. Voltando para a main

git switch main

04. Fazendo merge

Com a main ativa, merge junta nela as alterações da branch escolhida. 

git merge nova-feature
main ─────────●────────●
               \      /
                ●────●
                 feature

05. Enviando a branch

Publique a branch no GitHub para compartilhá-la ou abrir um Pull Request. 

git push -u origin nova-feature

06. Quando surge um conflito

O conflito acontece quando o Git encontra alterações incompatíveis e não consegue decidir qual deve permanecer. 

<<<<<<< HEAD
console.log("Olá");
=======
console.log("Hello");
>>>>>>> nova-feature
<<<<<<< HEAD início da versão atual======= separa as duas versões>>>>>>> nova-feature final da outra alteração

Resolvendo o conflito

Abra o arquivo, escolha o código correto, remova os marcadores, salve e registre a resolução. 

git add .
git commit -m "Resolve conflito"
Criar branch → Desenvolver → Commit → main → Merge → Conflito? → Resolver → Commit

Objetivo Escolher a ferramenta adequada para desfazer uma alteração, tirar algo do staging ou reverter um commit.

git restore arquivo.txt

Desfaz as alterações do arquivo e volta para a versão do último commit.

git restore --staged arquivo.txt

Remove o arquivo da staging area sem necessariamente apagar as alterações.

git revert ID_DO_COMMIT

Desfaz as alterações de um commit criando um novo commit, sem apagar o histórico.

git reset --hard ID_DO_COMMIT

Volta o projeto para um commit anterior e apaga as alterações posteriores. Use com cuidado.

Atenção ao reset --hard Esse comando pode causar perda de alterações não salvas. Confirme o estado do projeto antes de executá-lo.

Objetivo Trabalhar com outras pessoas sem alterar diretamente a branch principal e usando revisão antes do merge. 

GitHub  →  clone  →  criar branch  →  alterações  →  commit  →  push  →  Pull Request  →  revisão  →  merge

01. Cada pessoa usa uma branch

Branches isolam o trabalho de cada pessoa e evitam que mudanças incompletas cheguem direto à main. 

main
 │
 ├── feature-login
 │
 └── feature-dashboard

02. Adicione os colaboradores

Se outras pessoas precisarem trabalhar diretamente no repositório, o proprietário pode adicioná-las como colaboradoras em Settings → Collaborators. Depois disso, elas poderão trabalhar no projeto conforme as permissões concedidas.

03. Faça alterações e envie sua branch

Crie uma branch para sua tarefa, faça os commits e publique essa branch no GitHub. O push disponibiliza o trabalho para o restante do time. 

git switch -c minha-feature
git add .
git commit -m "Adiciona minha feature"
git push -u origin minha-feature

04. Abra um Pull Request

No GitHub, abra o repositório e clique em Compare & pull request ou em New pull request. Escolha main como base e minha-feature como branch de comparação.

Preencha um título objetivo e descreva o que foi alterado, por que a mudança é necessária e como ela pode ser testada. Revise os arquivos modificados e adicione os colaboradores responsáveis pela análise. 

base: main
compare: minha-feature

Título: Adiciona tela de login
Descrição: Explica a mudança e os testes realizados

05. Faça o Code Review

Os revisores abrem a aba Files changed para conferir o código linha a linha. Eles podem deixar comentários, sugerir melhorias ou aprovar a Pull Request.

Se pedirem mudanças, faça os ajustes na mesma branch e envie novos commits. A Pull Request será atualizada automaticamente. 

git add .
git commit -m "Ajusta revisão do login"
git push

06. Aprove e faça o merge

Quando os comentários forem resolvidos e as verificações passarem, um responsável aprova a Pull Request e seleciona Merge pull request. Depois, a branch pode ser excluída no GitHub se não for mais necessária. 

Branch → Alterações → Commit
   ↓
Push → Pull Request → Files changed → Review
                                      ↓
                              Aprovação → Merge
